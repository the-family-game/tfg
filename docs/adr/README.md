# Architecture Decision Records

Registriamo le decisioni tecniche importanti nel formato di [Michael Nygard](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions).

- File: `NNNN-titolo-in-kebab-case.md`, numerati in ordine, mai riutilizzati.
- Le bozze sono scritte da Claude e approvate dal maintainer tramite PR.
- Un ADR approvato non si modifica: se la decisione cambia, si scrive un nuovo ADR che lo **sostituisce** e si aggiorna lo stato del vecchio.
- Serve un ADR per: scelta o cambio dello stack, ogni nuova dipendenza esterna, ogni nuova astrazione architetturale (constitution P4), scelta della licenza.

Stati: `Proposto` → `Accettato`, oppure `Rifiutato`, `Deprecato`, `Sostituito da ADR-NNNN`.
